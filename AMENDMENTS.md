# AMENDMENTS.md

Per §8: "Where a design decision is ambiguous, implement the simplest version, log it in the manifest, flag it in `RESULTS.md`." This file is the record of every such ambiguity — what was ambiguous, what triggered noticing it, and which simplest-version reading was applied. Kept separate from `RESULTS.md`'s measured findings because these are resolutions to gaps in the preregistration text itself, not results of measurement.

---

## 1. §5.4's 0.65 threshold: raw or margin-residualized AUROC? (2026-08-24)

**The ambiguity.** §5.4 fixes: "Q2 fails if cross-condition transfer AUROC for arm A vs. arm B2 at position P2 is below 0.65 in Regime 1." Written before residualization existed as a measured quantity — §5.1's "regress out margin, re-probe" only became a concrete instruction once the P2 probe was actually implemented (Phase 3 canary run, `model/phase3_probe.py`, 2026-08-24). The text names one AUROC; measurement now produces two, raw and margin-residualized, and only one of them is anywhere near the boundary.

**What triggered noticing it.** The first canary run of the Phase 3 P2 probe (Regime 1, `real_seed_r1_0`) measured combo1's (L=2→3) residualized AUROC at `0.6460` — four thousandths below `0.65`. Raw AUROC for the same combo was `0.9977`, nowhere close. Deciding, in that moment, which reading §5.4 actually meant would have meant interpreting a genuinely ambiguous text right after seeing a number sitting at the boundary of it — the same shape of problem as moving a threshold after seeing test data, even though nothing about the *threshold itself* was in question, only which quantity it applies to.

**Resolution — simplest version, per §8: §5.4 reads on raw AUROC, exactly as written. The margin-residualized number is a separate, complementary condition from §5.1, reported alongside raw always, but does not itself carry a numeric falsification gate.** §5.4's text names one quantity, "cross-condition transfer AUROC," with no mention of residualization — the textually conservative reading applies the threshold to exactly what was written, not to a refinement invented after the fact. §5.1's margin-regression instruction stands on its own terms: report it, always, alongside raw AUROC — it is diagnostic information about how much of P2's separability survives once a raw retrieval statistic (margin) is accounted for, informative regardless of where it falls, but no threshold is retroactively assigned to it here.

**Consequence for the canary result.** Regime 1's raw AUROC (`0.9977` combo1, `0.9987` combo2) is nowhere near `0.65` in either combo — under this resolution, §5.4 is nowhere close to falsifying on this seed. This is not a pass verdict either: no falsification-or-confirmation verdict is drawn from a single seed, full stop — see `RESULTS.md`, and §2.6/§3.2's three-seeds-per-regime commitment, which exists precisely so no one run carries an interpretation on its own.

**Update (2026-08-24), because this ambiguity's own record needed one: the raw-vs-residualized reading extends to the Regime-2 magnitude threshold too (`AUROC≥0.80`, gap `≥0.15`), and is left open there for the same reason** — both regimes' raw AUROC are already saturated near `1.0` once a checkpoint has cleared §4.3, so the gap between them is close to zero under a raw reading regardless of any real difference in genuine signal. Not resolved here; flagged so it isn't quietly assumed either way once more seeds exist.

**What this resolution leaves standing, recorded as a limitation, not a hedge: §5.4-read-on-raw is close to unfalsifiable for any checkpoint that already cleared Phase 2.** Raw P2 AUROC (`0.998-0.999`) is almost entirely margin-explained (margin-only AUROC `0.991-0.996`, nearly matching raw). §4.3's B-arm criterion (`RESULTS.md` finding 14) already requires every checkpoint reaching Phase 3 to have margin discriminating present-key from absent-key queries at `AUROC≥0.70` — measured, on all six real seeds, at `0.9944-0.9990`. Since raw P2 AUROC is driven by essentially the same margin signal §4.3 already gated on, a checkpoint clearing Phase 2 is, by construction, most of the way to clearing §5.4-on-raw before Phase 3 even measures anything new. §5.4-read-on-raw is satisfiable, but not discriminating between "the state genuinely represents answerability" and "the state produces a query whose retrieval margin genuinely predicts success" — the second of which was already established in Phase 2, on different data, for a different reason. **The quantity that actually discriminates is the residual — which has no preregistered threshold, and per §8 cannot be assigned one now, after the fact.** A future reader who sees only "§5.4 cleared" should not read that as a strong Q2 confirmation; the raw-AUROC check that cleared is close to a formality once Phase 2 has already passed, and the residualized number — reported every time, on every seed, with no threshold to compare it against — is where the actual content of any Q2 claim has to live.

## 2. The END-flag control was scoped to Regime 2 only, and shouldn't have been (2026-08-24)

**The mistake.** `docs/phase1.md` §5.1 originally introduced the END-flag-identity regress-out as a Regime-2-specific control, reasoning from finding 11's END-guess-rate asymmetry under a foreign cache (Regime 2 checkpoints guess END-flagged entries roughly twice as often as Regime 1's). Finding 11 is a genuine regime asymmetry, and that made the scoping look justified.

**What triggered noticing it.** Running the control on Regime 2's canary and asking what mechanism explained the result: arm A's pos2 query is, by construction, the item's own correct END-retrieval — true for *any* checkpoint that solves arm A, independent of which regime trained it. B2's failure mode (a corrupted value, not a missing key) has no structural reason to land on an END entry regardless of training history. The explanation for why the control worked was never about Regime 2's training exposure to dead ends at all — it was about what arm A's pos2 position structurally *is*. A control justified by a regime-specific finding turned out to rest on a regime-independent mechanism, and the scope should have followed the mechanism, not the finding that motivated building it.

**Consequence.** Regime 1's own P2 result — the one number §5.4's falsification threshold is actually written against — had never been checked against this confound. Run immediately on discovery, before anything else: Regime 1's END-flag-only AUROC is `0.983-0.995`, as high as Regime 2's, and residualizing against it alone collapses Regime 1's margin-residualized signal (`0.646`/`0.713`) to chance (`0.496`/`0.545`) too. Extended further per the same logic: integration count (already shown to fully explain P1's raw signal, `RESULTS.md` finding 16) is not position-specific either, and was added as a third P2 control. **Jointly residualizing against all three (margin, END-flag, count) simultaneously collapses the P2 signal to chance in both regimes and both cross-condition combos** — `RESULTS.md` finding 19 has the complete numbers.

**Resolution.** `docs/phase1.md` §5.1 corrected to apply all three P2 controls to every checkpoint in either regime, not just Regime 2. `model/phase3_canary.py` replaces the two independently-written per-regime scripts (`model/phase3_run_canary.py`, `model/phase3_run_canary_r2.py`, kept for the historical record) with one shared function parameterized by checkpoint — the divergence between two near-duplicate scripts is exactly the kind of surface where a scope mismatch like this one can happen unnoticed, and a single shared implementation removes the surface, not just this one instance of the mistake.

**Broader lesson, worth stating since it generalizes beyond this one control: when a control's justification comes from a regime- or condition-specific finding, check whether the underlying *mechanism* is actually specific to that condition before scoping the control to it.** Finding 11 was real and regime-specific; the mechanism that made the control work was not. The two are easy to conflate when the finding is what prompted building the control in the first place.
